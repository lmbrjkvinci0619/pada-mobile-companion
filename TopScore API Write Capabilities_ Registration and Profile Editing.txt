TopScore API Write Capabilities: Registration and Profile Editing
Overview
This document addresses whether the TopScore API allows third-party mobile applications to perform write operations, specifically regarding league registration and profile editing. Based on the TopScore API specification and general platform capabilities, this analysis clarifies what's possible for a Pada.org mobile companion application.
________________


1. TopScore API Read vs Write Operations
1.1 API Design Philosophy
The TopScore API specification clearly distinguishes between read and write operations:
Operation Type
	HTTP Method
	Authentication
	Purpose
	Read Operations
	GET
	auth_token (optional for public data)
	Retrieve information
	Write Operations
	POST
	auth_token + api_csrf (required)
	Create, edit, delete, send
	1.2 Write Operation Requirements
According to the TopScore API specification:
"POST requests for everything else - creating new events, editing schedules, sending messages, and so on. They always require authentication."
All POST requests require:
1. 1.auth_token - User's Client ID
2. 2.api_csrf - HMAC-SHA256 signature with user's Client Secret
3. 3.SSL/HTTPS - All requests must be over SSL
4. 4.User-Agent - Header: TopScore API v1.0.0
1.3 API Response Structure
Both GET and POST responses use the same JSON structure:
json
{


 "status": 200,  // HTTP status code


 "result": [...], // Data array


 "count": 10,     // Total results


 "errors": []     // Error messages (if any)


}

2. Can Players Register for Leagues via API?
2.1 Registration Endpoint Availability
The TopScore API does include registration functionality. The typical registration flow involves:
Registration Endpoint: POST /api/registrations
Expected Capabilities:
* Create new registrations for leagues
* Create new registrations for teams
* Register for events/tournaments
* Handle associated payments (if TopScore payment integration is used)
2.2 Technical Requirements for Registration
To POST a registration, the mobile app would need:
1. 1.OAuth2 Authentication - User must be authenticated
2. 2.Registration Data - Including:
   * person_id - The user registering
   * league_id or team_id - What they're registering for
   * product_id - Registration product/fee selection
   * answers - Any registration form answers
3. 3.Payment Information - If fees are required
2.3 Critical Limitation: Third-Party API Access
⚠️ Important Finding:
The TopScore API documentation states:
"Since most organizations do not have a custom SSL certificate for their custom domain, API requests have to be done using our *.usetopscore.com domain, which is protected by our certificate."
This indicates that:
* API access is through the organization's subdomain (pada.usetopscore.com)
* TopScore controls API access at the organization level
* Third-party applications may require explicit approval from Pada.org/T

3. Can Players Edit Profile Information via API?
3.1 Profile Editing Endpoint
The TopScore API typically includes profile management:
Profile Update Endpoint: POST /api/persons/{person_id}
Expected Editable Fields:
* first_name
* last_name
* phone_number
* emergency_contact
* address
* profile_picture
* Custom profile fields configured by Pada.org
3.2 Profile Edit Requirements
1. 1.Authentication - User must be authenticated with OAuth2
2. 2.Authorization - User can typically only edit their own profile
3. 3.Validation - Field validation according to TopScore rules
4. 4.Audit Trail - Changes are logged by TopScore
3.3 Non-Editable Information
Some fields may be restricted from API editing:
* email - Often requires separate verification flow
* role - Admin-controlled, not user-editable
* organization_membership - Admin-controlled
* registration_history - Immutable records

5. Security and Access Control Considerations
5.1 OAuth2 vs Basic Auth for Write Operations
The TopScore API offers two authentication levels:
Basic Authentication:
* Lower security
* Limited data access
* Suitable for read-only operations
* Uses auth_token only
OAuth2 Authentication:
* Higher security
* Full data access
* Required for write operations
* Uses Bearer token in Authorization header
5.2 Write Operation Security
Write operations are protected by:
1. 1.Authentication Required - Valid user credentials
2. 2.CSRF Protection - HMAC-SHA256 signature prevents replay attacks
3. 3.Role-Based Access - Permissions control who can perform what actions
4. 4.Organization-Level Control - TopScore/Pada.org can restrict API access
5.3 Third-Party Application Restrictions
TopScore may impose restrictions on third-party applications:
* API Key Approval - Applications may need approval to access write endpoints
* Rate Limiting - Limits on POST requests per user or application
* Feature Restrictions - Some features may be disabled for third-party access
* Audit Logging - All API access is logged for security review

6. Recommendations for Mobile App Design
6.1 Conservative Approach (Recommended)
Given the uncertainty around write operation access, follow this approach:
Phase 1: Read-Only Companion
* Focus on read-only features initially
* Display registrations, team info, schedules
* Allow chat via Supabase (custom implementation)
* Launch with limited scope, prove value
Phase 2: Add Write Features (After Verification)
* Test write endpoints with Pada.org test account
* Verify registration flow works end-to-end
* Confirm profile editing syncs correctly
* Add features incrementally
6.2 Verification Checklist
Before implementing write features, verify:
*  Confirm TopScore API supports third-party registration POST
*  Obtain OAuth2 credentials for mobile app
*  Test registration flow in staging environment
*  Verify payment processing integration
*  Check TopScore terms of service for API usage restrictions
*  Confirm data validation rules
